# G2 Snap 2.8 — исправления «непредвиденных ситуаций»

APK собран из `G2Snap-2.8.apk` через apktool: smali-врезки + отдельный `classes8.dex`
с классами `Fix*` (исходники в `src/`). Подпись — debug-ключ (`~/.android/debug.keystore`).
Ниже каждая врезка описана так, чтобы её можно было перенести в исходный код на Kotlin.

## 1. Зрение: красная рамка у незагрузившегося фото (FixVision + FixRedMarks)

* `res/xml/accessibility_service.xml`: `android:canTakeScreenshot="true"`.
* `Runner$waitPhotos$result$1.invokeSuspend` сразу после `val a = Finder.attachments(...)`:
  ```kotlin
  if (FixVision.photoCheck(this@Runner, snap, pkg, input, a.failed)) return null // ждём дальше
  ```
* `FixVision.photoCheck`: раз в 600 мс асинхронный `takeScreenshot`, анализ полосы экрана над
  полем ввода (`input.top - 800 … input.bottom + 60`). Логика:
  * надпись «Upload failed»/«Не удалось загрузить» → нажать на неё (до 3 раз);
  * красная рамка, которая видна на двух снимках подряд **и обрамляет миниатюру**
    (совпадает с границами элемента или вмещает его ≥ 60 %) → нажать в центр
    (все сбойные фото одним жестом, до 3 кругов);
  * рамка **внутри** ImageView (часть фото) или не похожая на миниатюру → только запись в лог;
  * 3 круга не помогли → `StepFailed("Фото не загрузилось в DeepSeek (красная рамка после 3 повторов)")`
    и `diag/screen-upload-failed.png`.
* `FixRedMarks.find`: маска «красных» пикселей (R≥150, R−G≥70, R−B≥55), связные области,
  рамка = ≥3 закрашенных края, пустая середина, ровный фон снаружи.
  Тест: `test/…/FixRedMarksTest.java` (9 случаев, в т.ч. рамка внутри фото, поля тетради).

## 2. Повтор шага после «не той вкладки» (FixRecovery)

* `Runner.step` переименован в `stepOrig` (public), путь возобновления в `Runner$step$1`
  вызывает `stepOrig`; новый `step` = `FixRecovery.step(this, title, block, cont)`.
* Для шагов «Открываю DeepSeek», «Новый чат» → перезапуск DeepSeek
  (`FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK`); «Открываю Even Realities»,
  «Открываю Teleprompt» → перезапуск Even; «Создаю сценарий» → «Назад».
  Затем шаг выполняется ещё раз. Не больше 2 восстановлений за прогон, только для `StepFailed`.
* На Kotlin это проще: `try { block() } catch (e: StepFailed) { recover(); delay(…); block() }`.

## 3. Защиты от попадания не туда (FixGuards)

* `Runner.calibrated`: после `sig.find(...)` —
  `if (!FixGuards.calibratedOk(sig, node)) return null`. Обученная кнопка не принимается,
  если у элемента на её месте **другая подпись** («Edit», «Conversate» ≠ «New»).
  Это причина обоих реальных сбоев: 25.09 (Edit на карточке) и 28.09 10:52 (Conversate).
* `createScript$lambda$0$3/4` (ожидание редактора): редактором считается экран с полем
  «Enter text» или ≥ 2 полями ввода — `FixGuards.scriptEditorReady`.
* `createScript` (цикл попыток) и `insideTeleprompt`: карточка старого сценария
  (видны Edit + Start) → «Назад» и новый снимок (`leaveCardIfShown`).
* `LiveKt.captureNow` → `FixGuards.onCapture`: экран Samsung «Защита от случайного касания»
  (`com.android.systemui`, id `unintentional_*`) → жест «смахнуть вверх».
  **На устройстве не проверено** (эмулятор не умеет этот экран).

## 4. Диагностика

* `Runner.failure` → `FixVision.onFailure`: `diag/screen-fail.png` — снимок экрана в момент
  ошибки (во время ожидания фото — последний кадр анализа, без задержки).
  Попадает в «Поделиться логом и дампами».

## 5. Нет интернета (проверено на телефоне 28.09)

На реальном DeepSeek без сети было два варианта: (а) миниатюры с красной рамкой, «↻» в центре
и красным «×» (удалить) в углу — G2 Snap нашёл обе рамки и нажал «↻», «×» не трогал;
(б) DeepSeek молча не принял фото и не отправил сообщение, а G2 Snap ждал ответ 300 с.

* `FixRecovery.step` перед «Открываю DeepSeek»: нет сети → ждёт до 20 с (без блокировки потока),
  появилась — продолжает; нет — `StepFailed("Нет интернета на телефоне — …")`, без перезапусков.
* `Runner.waitAnswer` после `sample(...)` → `FixGuards.answerCheck(this)`: сеть пропала > 20 с
  во время ожидания ответа → ошибка сразу, а не через таймаут из настроек.
* `ErrorText.forGlasses` → `FixGuards.glassesText`: на очках «Ошибка: нет интернета /
  Включите интернет и повторите».
* «Сеть есть» = есть активная сеть с возможностью INTERNET (без проверки VALIDATED, чтобы не
  ломаться там, где Google-проверка связи недоступна).

Телефон без сети: было — 5+ мин ожидания и «DeepSeek не ответил»; стало — 20 с и «нет интернета».
Тестовый инструмент: `uiautomator dump` отключает службы спецвозможностей — не вызывать во время прогона.

## 6. Промпт для любого предмета (`PROMPT.txt`)

Стандартный промпт (`core/Prompt.DEFAULT`, заменён `scripts/patch_prompt.py`) был заточен под
физику и математику («ответ + шаги решения», блок «Как писать математику»), поэтому на русском,
биологии и т.п. DeepSeek отвечал не по заданию. Новый:
* перечисляет все школьные предметы и требует выполнить КАЖДОЕ требование формулировки
  («спишите», «вставьте», «выпишите», «объясните», «переведите», «разберите»…);
* длина по типу задания: расчётная задача — «Ответ:» с единицами + 3–8 строк решения
  (обычно 250–600 символов); тест — только вариант; русский — ровно то, что велит задание
  (весь текст при «спишите», вставленные буквы ЗАГЛАВНЫМИ, списки при «выпишите», разбор по схеме);
  теория — 2–5 предложений; «назовите три» — ровно три; сочинение — нужного объёма;
* если выделено одно задание из нескольких — решает его;
* первая строка по-прежнему «Ответ:» (на неё опирается `AnswerExtractor`), ограничения очков
  (символы, без Markdown/LaTeX) не менялись.
Если на телефоне в настройках сохранён свой промпт, он имеет приоритет — нажмите
«Вернуть стандартный промпт».

## 7. DeepSeek игнорировал «Поделиться», если уже был запущен (проверено на телефоне 28.09)

Если процесс DeepSeek уже жил (а после каждого прогона G2 Snap сам открывает в нём новый чат),
интент `ACTION_SEND` доходил до `ShareProxyActivity`, но DeepSeek показывал пустой чат: ни фото,
ни текста. G2 Snap писал «Миниатюр фото не видно — дальше проверит «Отправить»», отправлял промпт
без фото, и на очки приходило «Не видно: на фото нет изображения». Со свежим процессом (после
`force-stop`) фото приходило. Воспроизводилось стабильно: 3 из 3 «тёплых» прогонов без фото.

* `Share.send`: к флагам интента добавлен `FLAG_ACTIVITY_CLEAR_TASK`
  (`0x10000001` → `0x10008001`). Задача DeepSeek пересоздаётся, окно разбирает «Поделиться» как
  при холодном старте; процесс остаётся «тёплым», поэтому это быстро (~1 с).
* На Kotlin: `intent.addFlags(FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_CLEAR_TASK or FLAG_GRANT_READ_URI_PERMISSION)`.

## 8. Промпт: без лишних попыток фокуса (Runner.putPrompt)

Когда промпт отправлен вместе с фото (`promptShared`), `putPrompt` сначала вызывал `focusField`:
три нажатия на поле по ~0,9 с, ни одно не «подтверждало» фокус (поле DeepSeek — нативный EditText
внутри Compose, в дереве спецвозможностей его нет, клавиатура службы к нему уже подключена), и
лишь потом читал поле через клавиатуру службы — чтение срабатывало сразу.

* `putPrompt`, ветка `promptShared`: вместо `focusField` сразу переход к `Typist.read`
  (`move-object v3, v1` + `goto :cond_9`). Если промпт не найден, исходный путь печатает его
  (`enterText` → select-all + commit, текст заменяется, дубля нет).
* На Kotlin: `if (promptShared) { val t = Typist.read(svc); if (t.has(want, tail)) return }` без `focusField`.
* Запас на загрузку фото (1,8 с с момента, когда видна миниатюра) **оставлен**: DeepSeek не
  показывает загрузку ни в дереве, ни кнопкой «Отправить», а нажатие во время загрузки молча
  игнорирует — проверено с фото 2,2 МБ и запасом 0,1 с: повтор через 3 + 2 с, «Отправляю» 6,0 с.

## 9. Зум камеры (FixZoom)

* `MainActivity.setupTapToFocus` → в конце `FixZoom.attach(this, preview)`.
* Щипок двумя пальцами по превью — плавный зум (до `min(maxZoom, 10×)`); касание одним пальцем —
  фокус, как раньше (вызывается исходный `setupTapToFocus$lambda$0`).
* Над нижней панелью — кнопки «1× 2× 3×» в стиле приложения (зелёная — текущий зум, во время
  щипка показывает точное значение, например «2.4×»). Кнопок выше `maxZoom` камеры не видно.
* Зум переживает отправку: CameraX сбрасывает его на 1×, когда поверх открыты DeepSeek/Even —
  `FixZoom` после `onResume` применяет выбранный зум заново (0,25–2 с, пока камера открывается).
  После перезапуска приложения — снова 1×.

## Состав папки

* `app-smali/` — проект apktool (smali + ресурсы) с уже внесёнными врезками; сборка:
  `java -jar apktool.jar b app-smali -o unsigned.apk`, затем добавить `classes8.dex`
  (компиляция `src/` против `stubs/`, см. `scripts/build-fix.sh`), zipalign, apksigner.
* `app-java/` — декомпилированный (jadx) Java-код пакета `io.github.ewfefrs.g2snap`, только для чтения.
* `src/`, `stubs/`, `test/` — исходники классов `Fix*` (`FixZoom` — в пакете `io.github.ewfefrs.g2snap`)
  и заглушки для компиляции.
* `G2Snap-2.8-fix.apk` — последняя сборка (новый промпт + все исправления + п. 7–9), подпись
  debug-ключом; установлена на телефон 28.09 23:42.
